# Release v2026-10-23.2 — evidence

Impact: additive

## What changed

The `- Host: \`host[:resource]\`` line is now recognised in `TASK-DESCRIPTION`, and
the corpus has a fixture that proves it.

## Why

`2026-10-23.1` added `host` to the table's operation list and to the
documentation, and stopped there. The validator has a second place where
operations are named — the pattern that reads operation lines out of
`TASK-DESCRIPTION` — and it still listed five verbs. So:

```
prompts/tasks/02-datasets-volume-create.md: TASK-DESCRIPTION has no '- <Verb>: `path`' operation line
```

The release announced a capability that did not work, and no test objected.

## Why nothing objected

`13-corpus-coverage` requires a fixture **per numbered check**, not per accepted
operation. `2026-10-23.1` extended a check without extending its corpus, and the
coverage rule could not see it. This release adds an acceptance case that declares
a host operation and no repository file, so the operation is now exercised, not
merely listed.

That is the same lesson as `2026-10-22.5`: a test that cannot fail for the right
reason is not a test. Here the missing failure was coverage of a new branch.

## Machine-checkable evidence

- `00-homelab`: task `02-datasets-volume-create` conforms with two `host` rows and
  two `Host:` lines.
- Corpus in that project: 54 rejected, 7 accepted — the new acceptance case passes.
- Library suite: 9 tests.

## Behavioral evidence

Not applicable: no instruction an agent follows changed. What changed is whether a
task that changes only host state can be expressed at all.
