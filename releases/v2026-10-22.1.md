# Release v2026-10-22.1 — evidence

Impact: initial

A release record exists to answer one question at a later date: *what was true
when this tag was cut?* The shared rules are the instructions an agent follows,
so "the tests passed" is necessary but not sufficient; the behavioral cases in
`evals/` are the other half, and a person runs and scores those.

## What this version is

A faithful extraction. Every file in `MANIFEST` was copied byte-identically from
`00-project-skeleton`, which is where these rules were being maintained. No rule
was reworded, reordered, or renumbered in the move.

- `MANIFEST`: 36 files.
- `prompts/`: 28 files — contract, workflow, conventions, `README.md`, one
  universal-rules file, nine capability conventions, two flavors, four
  `how-to-write-*`, two episode templates, one shared feature file.
- `evals/`: 6 cases.
- `tests/`: the contract validator (`09`), its adversarial corpus (`10`), the
  corpus-coverage check (`13`), shared helpers, and `README.md`.
- `records/README.md`, `scripts/rules-check.sh`.

## Machine-checkable evidence

Run `make test` in this repository at the tag:

| Check | Proves |
|---|---|
| `00-manifest` | every shared file is listed; every entry exists; the changelog names the version |
| `01-vendor` | a clean vendor produces a conformant project; re-vendoring is a no-op |
| `02-integrity` | an edited, deleted, or unpinned file is refused, and forcing restores conformance |
| `03-overlay` | extending is allowed, restating shared text is refused, a stale deviation anchor is refused |
| `04-skeleton-integration` | vendoring into a complete project changes no existing file, and the shared validator accepts the result |

The `04` assertion is the faithfulness proof: vendoring into a copy of
`00-project-skeleton` reports **0 updates**, so no pre-existing shared file
needed to change to reach v2026-10-22.1.

## Known downstream state

At extraction, 16 projects carried copies of these rules: 18 copies of
`prompts/01-contract.md` in **8 distinct versions**, and 4–5 variants of the
validator. The oldest copies (146 lines against the current 189) are missing
the safety-and-privacy precedence level and the workflow-authorization wording,
so the difference between variants is behavioral, not cosmetic.

No project is migrated by this release. Each upgrade is a separate task that
records the before/after version, the changelog entries, the `rules-check`
result, and the eval run — one project at a time, so a defect in the shared
layer has one blast radius rather than sixteen.
