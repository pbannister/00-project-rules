# Release v2026-10-22.4 — evidence

Impact: additive

## What changed

Projects can declare the root files and directories the shared list cannot know
about. A project that declares nothing is unaffected: with no local rule file
carrying a `## Project Structure` section, the declaration set is empty and
checks 9 and 14 behave exactly as they did at `2026-10-22.3`.

## Why

The canary adoption of `archive-innov-k6` stopped here. Section 7 of the contract
already said:

> A derived project may declare additional canonical or tool-specific root files
> or directories in its project rules; the declaration makes them part of the
> project structure.

No validator implemented it. Checks 9 and 14 tested every tracked root file and
top-level directory against section 7 alone, so the canary was refused for
`LICENSE`, `PHASES.md`, `config.example.json`, `pyproject.toml`, and `research/`.
`LICENSE` is enough to block essentially every real project, so this was not a
canary problem; it was a hole in the shared rules that the canary made visible.

The fix reads declarations from local rule files only — `prompts/1x-…`, which
check 8 already exempts from the registry. A vendored file is never read, so a
declaration cannot be parked in a shared file to loosen every project at once.

## Machine-checkable evidence

`make test`: six tests.

| Test | Proves |
|---|---|
| `05-declaration` (new) | undeclared `LICENSE`, `pyproject.toml`, `research/` are refused; declared, the same project validates; a renamed heading is not a declaration |
| `04-skeleton-integration` | a complete project with this version vendored still validates |
| `00-manifest` | `CHANGELOG.md` names this version; every shared file is listed |

## Behavioral evidence

Not applicable: no instruction an agent follows changed. The contract and the
validator now agree about a structural fact, and a project that declares nothing
sees no difference. The next real check is the canary itself, which this release
unblocks but does not complete — a project that never ran the validator still
carries its own non-conformance, which is a separate task.
