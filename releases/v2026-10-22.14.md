# Release v2026-10-22.14 — evidence

Impact: wording

## What changed

One sentence in `prompts/03-conventions.md`. No rule changes meaning, and no
adopter must do anything.

## Why

`scripts/skeleton-diff.sh` was the original drift detector: it compared a
project's copies of the shared files against the skeleton and reported
differences. `scripts/rules-check.sh` replaced it — it runs in the project's own
suite, fails on an edited vendored file instead of reporting it afterwards, and
needs no sibling checkout.

Keeping both was the mistake this library is built to avoid: two mechanisms
answering the same question with different rules. Its cost was concrete. The
rename in `2026-10-22.9` left the script's file list naming a path that no longer
exists, and two projects (`gnome-vcard-integration`, `gnome-pkpass-integration`)
failed their own suites until each was repaired by hand. Every remaining
skeleton-lineage project carries the same latent break.

The shared conventions also told projects to keep forks of shared text in sync
with the script — advice that contradicts the checksum model, where a fork of a
vendored file fails the check rather than being reconciled.

## Machine-checkable evidence

- `grep skeleton-diff` over `MANIFEST` returns nothing.
- Library suite: 9 tests, including `08-shared-references`, which now has no
  dangling script reference to miss.
- The six projects that carry the script delete it themselves, with their own
  commits, and their suites pass afterwards.
