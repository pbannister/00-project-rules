# Release v2026-11-05.1 — evidence

Impact: additive

## What changed

- `prompts/capabilities/06-execution-boundary.md` section 4: a failure observed from
  inside the boundary is evidence about the boundary first, and about the host second.
  The anomaly is tested for breadth before it is called a host defect, a host fault is
  reported only after it reproduces outside the boundary, and no host change is
  proposed from an observation made inside the boundary.
- `evals/07-sandbox-attribution.md`: the behavioral case.

## Why

A deploy failed inside an agent sandbox with `Bad owner or permissions` on a system
SSH configuration file. The sandbox remaps file ownership, so root-owned files appear
as an unmapped user; the host file was correct. The agent concluded twice that the
host was misconfigured and advised changing the file. The rule makes the layer
attribution explicit and gives the agent a check to run before blaming the host.

## Machine-checkable evidence

- The rules suite passes; the end-to-end vendor test validates the skeleton with this
  version.
- `evals/07-sandbox-attribution.md` is listed in `MANIFEST`, so a copy is present in
  every project that pins this version.

## Behavioral evidence

Not run. The case exists, but no result is claimed: a pass needs a fresh session and a
human scorer, and this record must not assert one.
