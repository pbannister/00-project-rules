# Release v2026-10-22.7 — evidence

Impact: additive

## What changed

A new vendored tool, `scripts/rules-conform.sh`. No rule changed, so a project
that does not run it behaves exactly as before.

## Why

Two adoptions made the shape of the work obvious and the reporting useless:

- the canary: 20 findings, five files;
- `09-language-elseon`: 105 findings, twenty-one files, of which 62 were the same
  four missing task sections repeated across twelve tasks, and 43 were
  "requirement without an identifier" repeated across four features.

The validator says one finding per line, in file order. That is the right output
for a machine and the wrong output for a person planning the work: the actual
task — "twelve tasks need the same four sections" — is invisible in a hundred
lines of near-identical text.

## What it does

Runs the validator, then groups findings into a category table (entry point,
structure declaration, shared registry, single home, requirement identifiers,
unresolved reference, task format, unattended and safety, capability listing),
gives each category the one action that fixes it, and names the files it touches:

```
rules-conform: 105 findings in 21 places, pinned 2026-10-22.5

1. task format: 62 findings in 12 files
   add operation lines such as `- Create: documents/x.md`, a TASK-FILES table,
   TASK-VERIFY, and the closing OUTPUT: restatement
   - prompts/tasks/10-fork-or-extend-decision.md (6)
   ...
```

`--verbose` adds every finding under its action. Exit status is 0 when the
project conforms, 1 when it does not, 2 when the validator is absent — so it can
gate without being run in a project that has not adopted yet.

## The design constraint

It reports and it does not repair. Automatic repair is the tempting next step and
it is wrong: a tool that wrote requirement identifiers would be inventing the
requirement identifiers it then checks, and the check would certify its own
output. The semantic work — which task accepts which requirement — is the work.

## Machine-checkable evidence

`tools/tests/06-conform.sh`: a clean project is quiet; a project with a stray root
file, a stripped task and stripped identifiers reports exactly those three
actions and names the files; `--verbose` keeps the individual messages; the
reporter leaves every file byte-identical; a project without the validator exits
2. Library suite: 7 tests.

## Behavioral evidence

Not applicable: nothing an agent reads changed. The version is additive in the
only sense that matters — the rules an agent follows are untouched.
