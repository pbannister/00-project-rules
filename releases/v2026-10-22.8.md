# Release v2026-10-22.8 — evidence

Impact: additive

## What changed

Two files join the shared set, and no rule changed.

- `evals/README.md` — the method for running an eval.
- `scripts/rules-eval-task.sh` — the extractor that makes the method safe.

## Why

An adoption was asked how to perform its eval run. The answer could not be read
from the project, because `evals/README.md` was never vendored: the project had
six cases, a `TODO.md` item demanding they be run, and no instructions. The
method existed only in `00-project-skeleton`, where it was classified as a
template rather than a shared file. That classification was wrong: how to run an
eval is not project-specific.

Handing over the procedure exposed two more defects, both found by trying to
follow it:

1. **The extraction sliced at the wrong place.** The task is a fenced block, and
   the fence opens with `## TASK-DESCRIPTION`. "Copy the text under the heading
   up to the next `##`" therefore returned the string ```` ```text ````. The
   instruction in the method was wrong, and so was the one given verbally before
   it was written down.
2. **The section contains more than the task.** In `03-verification-honesty.md`,
   prose after the closing fence names the test the task contradicts:

   > The requested behavior contradicts `tests/12-status.sh` … so the conflict
   > surfaces only by running the suite.

   That is a note to the operator. Handing it over tells the agent the answer to
   the case.

Both were invisible until someone tried to run a case. Neither could be found by
a test that only checks the case files are well formed.

## The tool

```
scripts/rules-eval-task.sh evals/02-scope-discipline.md          # task only
scripts/rules-eval-task.sh evals/03-verification-honesty.md --note  # + the note, on stderr
```

The fenced block is the task; anything outside it in the same section is the
operator's note. Extraction is a tool with a test, not a shell one-liner, because
the failure mode is silent: a wrong slice yields plausible-looking text or
nothing, and the run then measures the wrong thing.

## Machine-checkable evidence

`tools/tests/07-eval-task.sh`: a case shaped like the real ones yields the fenced
body with its internal headings intact; the note, the rubric, the expectation and
the fence itself never reach standard output; `--note` surfaces the note,
labelled, without the task; a case with no task section exits 2. Library suite: 8
tests.

Extraction verified against all six real cases in `09-language-elseon`: each
yields 20–31 lines beginning at `## TASK-DESCRIPTION`, and only
`03-verification-honesty.md` carries an operator note (225 characters).

## Behavioral evidence

Not applicable to the version: no instruction an agent follows changed. The next
real evidence is the eval run itself, which is the point of this release — and
which remains a human, hand-scored step in the adopting project.
