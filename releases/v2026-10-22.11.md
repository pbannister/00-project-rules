# Release v2026-10-22.11 — evidence

Impact: wording

## What changed

One dependency edge removed from a shared feature, two eval cases repointed, and
a guard that makes the whole class of defect reportable here rather than in a
project.

## Why

`00-llm-integration` conformance reached a single remaining finding, in a file it
does not own:

```
prompts/features/02-project-pages.md: feature dependency does not resolve: 01-site-build.md
```

`02-project-pages.md` ships with the rules. `01-site-build.md` is a skeleton
feature. Every project that does not model a site build the way the skeleton does
therefore failed a check on a locked file it could not edit.

The guard written for it then found two more instances immediately, in eval cases
`01` and `05`, both of which named the same skeleton feature as a `TASK-FEATURES`
entry. Those cases could not run in most projects for a second reason beyond their
`## Requires` list.

## The recurring defect

| Instance | Shared artifact | Assumed |
|---|---|---|
| eval cases need `scripts/status.sh` | `evals/*.md` | skeleton scripts |
| episode workflow example | `how-to-write-tasks.md`, `01-episode-template.md` | skeleton feature |
| page feature dependency | `02-project-pages.md` | skeleton feature |
| two eval tasks | `evals/01`, `evals/05` | skeleton feature |

All four are one mistake: **shared material written against the template's
inventory.** Each was found by a project, never by a test, and each cost a release.
`tools/tests/08-shared-references.sh` now enforces the sharpest form of the rule —
a feature file is project-specific by definition, so a shared file may only name
one that is itself shared. It excludes `tests/`, whose generated fixture paths are
not references, and allows the `00-features.md` index, which every project carries
by convention.

## Machine-checkable evidence

- `08-shared-references`: 34 shared files, no project-specific feature reference.
  Before the fix, four references failed it.
- Library suite: 9 tests.
- `00-llm-integration` check 2 and check 10 report no finding after adopting this
  version.

## Behavioral evidence

Not applicable: no instruction an agent follows changed. The dependency edge
affected only which acceptance identifiers a task may cite transitively; each
project's own suite verifies that after adoption.
