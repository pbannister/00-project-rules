# Release v2026-10-22.15 — evidence

Impact: additive

## What changed

The adversarial corpus falls back to the working tree when the project's git
index is empty. A project with commits is unaffected.

## Why

Two projects in this workspace — `cad-migration` and `design-phased-array` — are
git repositories that have **never been committed**. Their index is empty.

`2026-10-22.6` made the corpus build its fixture from `git ls-files`, which is
right: the validator only ever reads tracked files, and copying a 3.9 GB working
tree per case was the alternative. But an empty index produced an empty fixture,
and the corpus then reported 54 failures that named the rules:

```
contract section 2 (authoritative rules) not found
AGENTS.md is missing
rule family 'instruction precedence': marker not found
```

None of that was true. The repository was the problem, and those messages sent
the reader looking at the wrong thing.

## The fix

When `git ls-files` returns nothing, copy the working tree as the corpus did
before `.6`. That is the only state a never-committed repository has. Its pin test
reports the real condition separately: a project with no index cannot verify a
pin, and saying so is more useful than a fabricated rules failure.

## Machine-checkable evidence

- `cad-migration` and `design-phased-array`: the corpus now reports
  `54 rejected, 6 accepted` from a working-tree fixture.
- The library suite: 9 tests. `00-project-skeleton`, which is committed, still
  uses the tracked path and reports the same counts.

## Behavioral evidence

Not applicable: the corpus is the harness, not a rule.
