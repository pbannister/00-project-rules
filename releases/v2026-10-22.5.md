# Release v2026-10-22.5 — evidence

Impact: wording

## What changed

Three fixtures in the adversarial corpus now force-add the file they create. No
instruction an agent follows changed; the project's own suite simply stops
passing or failing for the wrong reason.

## Why

Adopting the rules into `archive-innov-k6` turned `10-prompt-validator.sh` red
with:

```
10-prompt-validator: the validator accepted [9] 'undeclared tool directory'
```

The case creates `.undocumented/config.json` and expects check 9 to reject the
undeclared tool directory. The canary's `.gitignore` ignores `config.json` — it
holds a camera WiFi password, so it is never committed — which meant
`git add -A` silently skipped the fixture. The directory was never tracked, so
check 9 never saw it, and the validator was "accepted" for a reason that had
nothing to do with the check under test.

This is a corpus defect, not a project defect. A project may ignore any of these
names for good reasons, and a fixture that is invisible makes a rejection case
pass silently — the most dangerous shape of test failure, because it looks green.

## The fix

`git add -f` on the fixture path only, in the three cases whose payload names a
project could plausibly ignore (`NOTES.md`, `.undocumented/config.json`,
`.vscode/settings.json`). The force never applies to the project's tree: a
project may legitimately carry gigabytes of ignored evidence, as this one does
under `research/`.

## Machine-checkable evidence

- `tools/rules-test.sh`: six tests.
- `archive-innov-k6`: `10-prompt-validator.sh` reports `54 rejected, 6 accepted`
  after the fix; before it, case 9 failed.

## Behavioral evidence

Not applicable: nothing an agent reads or follows changed. A `wording` release,
adoptable without an eval run.
