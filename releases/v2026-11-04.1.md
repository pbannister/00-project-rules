# Release v2026-11-04.1 — evidence

Impact: additive

## What changed

- The required-directory list appears once, in `prompts/01-contract.md` section 7, with
  one line of purpose per directory, behind a marker comment that tooling reads.
- `tests.out/` is a required directory for test working files, not version-controlled.
  A test writes only under `tests.out/<test-name>/`, clears it before it runs, and
  removes it only after it passes.
- `tests.out/` is a protected path. The validator reads the protected list from the
  contract rather than restating it.
- The outcome-record commit rule has one owner, `records/README.md`, enforced by a
  rule-family check.
- Rule strength is stated: MUST for an enforced rule, SHOULD for an unenforced one.

## Why this is additive, not wording

The validator now refuses a task that authorizes an operation on `tests.out/`, and it
refuses a restatement of the record-commit rule. Both are new checks, so a project that
relied on the old behavior sees new refusals. Nothing an agent already follows is
reversed, which is why the class is `additive` and not `breaking`.

## Machine-checkable evidence

- `tests/10-prompt-validator.sh`: a new protected-path case for `tests.out/`. A mutation
  check removed `tests.out` from the contract list and the case then failed, so it is
  load-bearing. Complete-project corpus: 55 rejected, 7 accepted.
- `tests/09-prompt-contract.sh`: the outcome-record family refuses a restatement in
  `prompts/02-workflow.md` (mutation checked) and passes on the single owner.
- `tests/09-prompt-contract.sh` now scans `records/README.md`, an authoritative file.
- `tools/tests/05-declaration.sh`: an undeclared `LICENSE` assertion was corrected; the
  skeleton declares `LICENSE`. It now checks an undeclared `pyproject.toml`.

## Behavioral evidence

Not run. No eval case in `evals/` changed, and the changes constrain what a task may
authorize rather than how an agent reasons. A human should still review the
`tests.out/` protected-path wording before adoption.
